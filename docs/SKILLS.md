# 20 skills, 20 bounded contributions

Reviewed November 12, 2026 from the local SI Atlas. This is a task-specific
selection, not a performance leaderboard. Usage and Atlas scores do not prove
quality. Antislop supplied the text-editing lens; the other sources contributed
bounded principles, not instructions to launch their workflows.

Applicable entry sections were read. Deep reference libraries and optional
scripts were not executed. The original source identities remain unchanged
when these contribution summaries are translated.

| Skill | Principle | ATS application | Limit |
|---|---|---|---|
| `superfast` | Measure total effort to acceptance. | Stop adding rounds after the contract is satisfied. | Compare speed only at equal acceptance. |
| `aiworkflow` | Define outcome and executable acceptance before tool choice. | Use one CLI core with explicit commands. | verify runs the supplied check without rewriting it. |
| `zeroloop` | Use the narrow affected check; stop after green. | just check bundles types and behavior tests. | Do not repeat an unchanged green check for reassurance. |
| `warm-handoff` | Use fewer requests on smaller context at real boundaries. | Keep long logs in files and return evidence paths. | No periodic keepalive or forced restart. |
| `synapse-recall` | Load prior decisions only when they change the next action. | Review existing benchmark evidence before rerunning it. | Bind changing claims to dated sources. |
| `agent-efficiency-orchestrator` | Optimize accepted work per total effort. | Reject saving claims when acceptance fails. | Report cost separately from time and quality. |
| `superiss` | Bind ownership, source and executable acceptance. | Use an explicit project database; create no second task board. | An ATS result is not a native SIS proof. |
| `best-defaults` | Choose a small reversible default with an override. | Installation shows a plan; --apply writes. | A project update does not authorize unrelated host changes. |
| `antislop` | Make each judgment a checkable statement. | Lead the evidence story with a counterexample. | Use slopcheck and an editorial deletion pass. |
| `thinkforward` | Look for the bottleneck and a way to falsify the claim. | Test whether a shorter view loses a needed failure signal. | Check exits and raw evidence; expose omissions. |
| `speedplaybook` | Identify the cost class before optimizing. | Measure cache cost separately from process time and output size. | Do not transfer a speed factor between workloads. |
| `loop2goal` | Choose the next step by its contribution to acceptance. | verify writes evidence for exactly one execution. | The result points back to its raw evidence. |
| `skill-portfolio-governance` | Review overlap and observed behavior before retirement. | Curate 20 contributions without loading 20 workflows. | Atlas score is not quality or a general ranking. |
| `verify-and-stop` | Distinguish pass, fail, unavailable and blocked. | Startup failure is 127; timeout is 124. | After correction, repeat only affected failed checks. |
| `researchflow` | Preserve sources and derive checkable findings. | Keep source hashes and relative benchmark links. | Separate measurements, estimates and proposals. |
| `autom` | Evaluate one bounded candidate and keep or reject it. | New defaults need repeated comparisons with fixed acceptance. | No automatic self-editing or paid model calls. |
| `context-budget` | Account for loaded rules, skills and tool definitions. | Keep a permanent broad tool registry out of the core. | Tokens-per-tool heuristics are not billing evidence. |
| `systematic-debugging` | Find the cause from diagnostics and reproduction. | Preserve complete stdout and stderr before shortening. | Empty or unusual diagnostics cannot turn a failure green. |
| `ratiomaster` | Measure user effort alongside actual success. | Provide a direct result, an install plan and a recovery path. | CLI time is not browser or customer UX evidence. |
| `ponytail` | Prefer existing paths and the standard library. | Use Bun and Node built-ins; no runtime packages. | No provider gateway, cron jobs or generic plugin framework. |

The [machine-readable selection](../data/skills-v5.json) contains the reviewed
SKILL.md hash and Atlas detail command for each source. A hash identifies that
text version; it does not establish an active integration. Host-specific source
paths stay local so this catalog remains portable.

## What is not activated

Some sources describe reviewers, background services, training or Python tools.
Reading them does not authorize those actions. ATS keeps the project contract
and adopts only the contributions above. A simulation or source test remains
different from actual customer acceptance.
